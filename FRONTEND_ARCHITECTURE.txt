1. PROJECT SETUP & INSTALLATION
================================================================================

PREREQUISITES:
  - Node.js 16+ (npm or yarn)
  - Git
  - Code editor (VS Code recommended)

INITIAL SETUP:
  1. Navigate to project directory:
     $ cd Enrolement-Frontend

  2. Install dependencies:
     $ npm install

  3. Create .env file (from .env.example):
     $ cp .env.example .env
     
     Edit .env with:
     VITE_API_URL=http://localhost:8080
     VITE_APP_NAME=BCP Enrollment Platform

  4. Start development server:
     $ npm run dev
     
     Output: Local: http://localhost:5173/

  5. Build for production:
     $ npm run build
     
     Output: dist/ folder ready for deployment

  6. Preview production build:
     $ npm run preview


VERIFY INSTALLATION:
  ✓ No console errors
  ✓ Dev server runs on localhost:5173
  ✓ Login page loads with BCP branding
  ✓ Can see Tailwind styles applied

  ✓ Hooks: Handle state + logic

  ✓ Types: Handle type safety
  ✓ Styles: Handle visual appearance

  API makes HTTP request
    ↓

4.3 LIFTING STATE
───────────────────

When multiple components share state, lift to common parent:

❌ WRONG (State in each component):
  PageA: const [data, setData] = useState();
  PageB: const [data, setData] = useState();
  
✓ CORRECT (State in parent):
  App: const [data, setData] = useState();
  PageA: <PageA data={data} onChange={setData} />
  PageB: <PageB data={data} onChange={setData} />

8. AUTHENTICATION FLOW
================================================================================

8.1 LOGIN FLOW
────────────────

USER LOGIN SEQUENCE:
  1. User navigates to /login (if not authenticated)
  2. User enters email + password
  3. Click "Sign In"
  4. LoginPage calls: await login(email, password)
  5. Hook calls: apiService.login(email, password)
  6. API call: POST /auth/login
  7. Backend validates and returns JWT token
  8. Token stored in localStorage
  9. User object stored in localStorage
  10. Zustand state updated
  11. Component detects isAuthenticated = true
  12. useEffect redirects to /dashboard
  13. Layout renders with Sidebar + Navbar

CODE EXAMPLE:
  const LoginPage = () => {
    const { login, error } = useAuthStore();
    
    const handleSubmit = async (e) => {
      e.preventDefault();
      try {
        await login(email, password);
        // Redirect handled by useEffect watching isAuthenticated
      } catch (err) {
        // Error displayed
      }
    };
  };

8.2 PROTECTED ROUTES
──────────────────────

PrivateRoute Component (src/components/common/PrivateRoute.tsx):
  - Checks isAuthenticated from Zustand
  - If true: render requested component
  - If false: redirect to /login
  - Optional: Check user roles for permission-based access

USAGE IN APP.TSX:
  <Routes>
    <Route path="/login" element={<LoginPage />} />
    <Route element={<PrivateRoute />}>
      <Route path="/" element={<Layout><DashboardPage /></Layout>} />
      <Route path="/users" element={<Layout><UsersPage /></Layout>} />
    </Route>
  </Routes>

8.3 LOGOUT FLOW
─────────────────

LOGOUT SEQUENCE:
  1. User clicks "Logout" in Sidebar
  2. Sidebar calls: logout()
  3. Zustand removes token, user, sets isAuthenticated = false
  4. localStorage cleared
  5. PrivateRoute detects isAuthenticated = false
  6. Auto-redirect to /login
  7. LoginPage rendered

AUTO-LOGOUT ON TOKEN EXPIRATION:
  1. User makes API request
  2. Backend returns 401 (token expired)
  3. Axios interceptor catches 401
  4. Interceptor calls: logout()
  5. Sequence follows logout flow above

8.4 SESSION PERSISTENCE
──────────────────────────

ON APP LOAD:
  1. App.tsx renders
  2. useRef(false) prevents double hydration
  3. useEffect calls: authStore.hydrate()
  4. Hydrate reads localStorage
  5. Loads token + user + sets isAuthenticated
  6. useAuth hook receives updated state
  7. PrivateRoute allows access if isAuthenticated

BENEFITS:
  ✓ Users stay logged in on page refresh
  ✓ No need to login again
  ✓ Automatic on app load


9. ERROR HANDLING
================================================================================

9.1 API ERROR HANDLING
──────────────────────

TRY-CATCH PATTERN:
  const handleCreateUser = async (userData: UserCreateRequest) => {
    try {
      const newUser = await apiService.createUser(userData);
      // Success
      showSuccessToast('User created');
      refreshUserList();
    } catch (error: any) {
      // Network error
      if (!error.response) {
        showErrorToast('Network error');
        return;
      }
      
      // Server error
      const status = error.response.status;
      const message = error.response.data?.message;
      
      if (status === 409) {
        setFieldError('email', 'Email already exists');
      } else if (status === 400) {
        showErrorToast(message || 'Invalid data');
      } else {
        showErrorToast('Server error');
      }
    }
  };

HTTP STATUS CODES:
  - 200-299: Success (no error)
  - 400: Bad request (validation error)
  - 401: Unauthorized (token expired, redirects to login)
  - 403: Forbidden (insufficient permissions)
  - 404: Not found (resource doesn't exist)
  - 409: Conflict (duplicate email, etc.)
  - 500: Server error (bug in backend)

9.2 FORM VALIDATION
─────────────────────

CLIENT-SIDE VALIDATION:
  const validateForm = (data: FormData): Errors => {
    const errors: Errors = {};
    
    if (!data.username) {
      errors.username = 'Username is required';
    }
    
    if (!data.email) {
      errors.email = 'Email is required';
    } else if (!isValidEmail(data.email)) {
      errors.email = 'Invalid email format';
    }
    
    if (data.password && data.password.length < 8) {
      errors.password = 'Password must be at least 8 characters';
    }
    
    return errors;
  };

FIELD-LEVEL DISPLAY:
  {errors.email && (
    <p className="text-red-500 text-sm mt-1">{errors.email}</p>
  )}

SERVER-SIDE VALIDATION:
  - Backend validates all input
  - Returns 400 with detailed errors
  - Display on corresponding fields
