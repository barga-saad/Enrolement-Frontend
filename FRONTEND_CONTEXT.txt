4. GESTION D'ETAT
================================================================================

authStore.ts (Zustand) :
  State : token, refreshToken, user, isAuthenticated, requiresPasswordChange
  Actions : login(), logout(), changePassword(), refreshUser(), setToken()
  Persistence : localStorage via helpers.storage

langStore.ts (Zustand) :
  State : lang ('fr' | 'en')
  Helper global : t(fr, en) — retourne le texte dans la langue active

toastStore.ts (Zustand) :
  State : toasts[]
  Actions : toast.success(), toast.error(), toast.info(), toast.warning()


5. SECURITE ET TOKENS
================================================================================

CONNEXION :
  1. Login -> POST /auth/login -> { token, refreshToken, expiresIn, ... }
  2. token stocke dans localStorage (authToken)
  3. refreshToken stocke dans localStorage (refreshToken)
  4. Axios intercepteur request : ajoute "Authorization: Bearer {token}"

EXPIRATION (401) :
  1. Intercepteur response detecte 401
  2. Recupere refreshToken du localStorage
  3. POST /auth/refresh { refreshToken } -> nouveau token
  4. Si succes : nouveau token stocke, requete originale retentee
  5. Si echec : clear localStorage + redirect /login

RBAC (4 profils) :
  - PROFIL_ADMIN_CENTRAL : acces complet
  - PROFIL_SAISIE        : creation et soumission partenaires
  - PROFIL_VALIDATEUR    : validation des soumissions
  - PROFIL_CONSULTATION  : lecture seule


6. PARTENAIRES — WORKFLOW
================================================================================

STATUTS WORKFLOW :
  DRAFT -> PENDING -> VALIDATED
               \-> REJECTED -> DRAFT (correction possible)

VUES DISPONIBLES :
  /partners/new      -> Formulaire creation
  /partners/drafts   -> Mes brouillons (DRAFT + REJECTED du user)
  /partners/edit     -> Modification partenaires VALIDATED
  /partners/validate -> Queue de validation (PROFIL_VALIDATEUR)
  /partners/consult  -> Consultation en lecture seule + timeline historique

FORMULAIRE PARTENAIRE (3 onglets) :
  Onglet 1 — Informations Generales :
    - Identite : nom, reference, type, statut, pays, classification
    - Compte bancaire
    - Types transactions : 6 types avec plafonds et commissions (Flat/%)
  Onglet 2 — Forex :
    - Reception devises : toggle + liste devises + plafond montant
    - Emission devises : toggle + type transaction + autorisations
    - Controle provision : nature paiement
  Onglet 3 — Conformite & Facturation :
    - Conformite DO (PARTNER only) : 6 toggles
    - Conformite Beneficiaire (PARTNER only) : 5 toggles
    - Fichier Synthese (PARTNER only) : 1 toggle (defaut: Oui)
    - Facturation : setup fee, billing mode, derogation, commissions


7. API — ENDPOINTS UTILISES
================================================================================

Auth :
  POST /auth/login
  POST /auth/refresh
  POST /auth/logout
  GET  /auth/me

Partners :
  GET  /v1/read/partners        (paginated, filterable)
  GET  /v1/read/partners/{ref}  (by reference)
  POST /v1/create/partners
  PUT  /v1/update/partners
  POST /v1/submit/{partnerId}
  POST /v1/save-draft/{partnerId}
  GET  /v1/export/partners?format=csv

Validations :
  POST /v1/validations/validate/{id}
  POST /v1/validations/reject/{id}
  GET  /v1/validations/pending
  GET  /v1/validations/drafts
  GET  /v1/validations/history/{partnerId}

Admin :
  CRUD /admin/users
  CRUD /admin/roles
  CRUD /admin/permissions
  GET  /admin/audit-logs
  GET  /admin/audit-logs/by-date-range
  GET  /admin/audit-logs/by-entity/{type}
